## 3. Deviations from Reference Design & Standards

1. **Theme & Stylesheet Fragmentation (`src/ops-console.css` vs `src/styles/ops-console.css`)**:
   - The reference architecture specifies a single scoped `.ops-root` token system where light and dark modes differ *only* in color tokens (`docs/theme-parity/rules.md`). Currently, `src/ops-console.css` retains a legacy `.staff-shell` theme while `src/styles/ops-console.css` implements `.ops-root`, and several pages import global `<Button>` and `<Card>` components that bypass `.ops-root` styling rules.
2. **Text-First Status Discipline vs Saturated Pastel Pills**:
   - Enterprise financial console standards require restrained, high-contrast status indicators (`pdot` + semantic text) rather than heavy multi-colored background pills on every table row (`styles/ops-console.css:211`).
3. **Tabular Numerals & Monetary Precision**:
   - Financial consoles require `font-variant-numeric: tabular-nums` on every currency column, KPI counter, SLA timer, and ledger balance. Currently, `Inter` proportional numerals are used on `.amount`, `.kv-v`, and `.acct-bal`, and `fmt()` strips fractional santims (`maximumFractionDigits: 0`), obscuring sub-birr reconciliation deltas.
4. **Safety UX on Money & Compliance Mutations**:
   - Several screens rely on raw `window.prompt()` / `window.confirm()` (`Escrow`, `Receipts`, `DisputeQueue`, `ReportsQueue`) or execute immediate 1-click mutations (`Payouts`, `KycQueue`), deviating from the required Summary Confirmation Modal pattern with explicit ETB amounts and audit reasons.

## 4. Proposed Shared Tokens & Components to Extract

1. **`ConfirmActionModal` (`apps/frontend/src/pages/ops/components/ConfirmActionModal.tsx`)**:
   - Standardized modal for all financial and compliance mutations (`Payouts`, `Escrow`, `Receipts`, `KycQueue`, `DisputeQueue`, `ReportsQueue`).
   - Displays: Action title, severity tone (`primary` / `green` / `red` / `amber`), structured summary KV grid (**Counterparty**, **Explicit ETB Amount** in `tabular-nums`, **Rail / Reference**, **Target Outcome**), optional or required **Reason / Audit Note** field with minimum-character validation, `Escape` key & backdrop close, and `busy` double-submit lock.
2. **Centralized Status & Tone Mapping (`apps/frontend/src/pages/ops/components/ui.tsx`)**:
   - Unified `TONE` and localized label dictionary covering all contract, payment, payout, escrow (`ADMIN_HOLD`, `WORK_IN_PROGRESS`, `SUBMITTED_FOR_REVIEW`), reconciliation (`MATCHED`, `MISMATCH`, `PENDING`), KYC (`UNDER_REVIEW`, `VERIFIED`, `REJECTED`), and dispute stage enums (`STAGE_1_NEGO` through `STAGE_4_ARBITRATION`).
3. **Tabular ETB Currency & Date Formatters (`apps/frontend/src/pages/ops/opsApi.ts`)**:
   - Update `fmt()` / `fmt2()` so financial amounts preserve exact decimal precision when non-zero (or on accounting surfaces) and always pair with `.tabular-nums`.
4. **Structured Skeleton Loader (`LoadingBox` in `components/ui.tsx`)**:
   - Replace the single-badge spinner with a layout-preserving skeleton header, 4-card KPI strip, and 6-row table skeleton to eliminate cumulative layout shift (`CLS`).
5. **Bilingual Operations Dictionary (`ops.*` in `apps/frontend/src/i18n.ts`) + Console Header Language Switcher**:
   - Full English (`en`) and Amharic (`am`) translations for navigation groups, screen titles, table headers, filter placeholders, status labels, and confirmation modals, toggled directly from `.ops-root .header`.
